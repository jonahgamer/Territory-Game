    Backups

    The full database is copied to the private GitHub backup repository every day at 02:00 Hong Kong time. The live database is always the top node. Restoring creates a safety snapshot first, then starts a new branch from the restored node.

    Restore selected backup

    The server will first create a safety snapshot of the current database and verify it. Only then will it replace the live database. Restoring an old backup can remove or change your own admin account, so you may be signed out afterwards.

    After a successful restore, an after-restore snapshot is written and a new branch starts from the selected node. The old branch remains in the tree.

    Enter the exact value of the server environment variable DSCONFIRM.
